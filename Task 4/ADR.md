### <a name="_3bfxc9a45514"></a>**Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| 1 | Сотрудник внутреннего колл-центра | Просмотр ставок по депозитам | Сотрудник получает доступ к актуальным ставкам через защищённый веб-интерфейс.          |
| 2 | Партнёрский колл-центр            | Получение данных о ставках   | Партнёр получает обновляемые файлы со ставками в согласованном формате (например, CSV). |
| 3 | Администратор системы             | Управление доступом          | Настраивает права и форматы выгрузки для партнёров.                                     |
### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| 1 | Безопасность доступа к ставкам                   | Ограничение доступа по ролям. Внутренний колл-центр — через авторизацию в системе, партнёр — через файлы с шифрованием. |
| 2 | Простота интеграции для партнёрского колл-центра | Передача информации в формате CSV/XLSX с регулярной выгрузкой.                                                          |
| 3 | Актуальность данных                              | Регулярное обновление файлов выгрузки (например, каждые 10 минут или по событию).                                       |
| 4 | Масштабируемость решения                         | Возможность подключения нескольких партнёрских колл-центров с разными форматами выгрузки.                               |
| 5 | Защита персональных и конфиденциальных данных    | Исключение персональных данных из файлов, шифрование файлов перед передачей.                                            |
| 6 | Устойчивость к нагрузке                          | Разделение потока выгрузки и онлайн-доступа, кеширование актуальных ставок.                                             |
### <a name="_qmphm5d6rvi3"></a>**Решение**
Приведите диаграммы контекста и контейнеров в модели C4. Опишите там основные компоненты и интеграции всех элементов решения. 

Обоснование:
* Для внутреннего колл-центра важна скорость и актуальность данных — выбран веб-интерфейс с авторизацией и ролевым доступом.
* Для внешнего партнёрского колл-центра проще и надёжнее использовать выгрузку файлов, т.к. это снижает технические барьеры для интеграции.
* Для безопасности реализуется шифрование файлов и исключение лишних данных (только ставки, без персональной информации).
* Кеширование и разделение логики доступа минимизирует нагрузку на основной модуль ставок.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
* **Предоставление API для партнёров** — отказались в пользу файлов, т.к. API требует больше ресурсов на интеграцию и безопасность.
* **Выдача общего доступа к интерфейсу внутренней системы** — небезопасно и неудобно для внешних партнёров.

**Недостатки, ограничения, риски**

* **Файловая выгрузка требует контроля за актуальностью и корректностью формата.**
* **При большом количестве партнёров нужно следить за безопасной маршрутизацией выгрузок.**
* **Ошибки в выгрузках могут повлечь искажение информации о ставках.**
* **Файлы нужно защищать от несанкционированного доступа и обеспечить журналирование их отправки.**
