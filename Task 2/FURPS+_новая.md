| Код  | Требования                                                                                 | Комментарий |
|------|---------------------------------------------------------------------------------------------|-------------|
| F   | Функциональные (Functionality)                                                   |             |
| F1   | Новый клиент может выбрать депозит и отправить заявку онлайн (ФИО, телефон).               |             |
| F2   | Менеджер обрабатывает заявку и связывается с клиентом.                                     |             |
| F3   | Зарегистрированный клиент видит персонализированные предложения.                           |             |
| F4   | Возможность выбора и открытия депозита онлайн без посещения офиса.                         |             |
| F5   | Подтверждение открытия счета через СМС.                                                    |             |
| F6   | Управление ставками по депозитам через модуль с разграничением доступа для подразделений. |             |
| U   | Удобство использования (Usability)                                                  |             |
| U1   | Удобный и быстрый интерфейс в мобильном приложении и веб-версии.                          | Важно для повышения конверсии и удержания клиентов. |
| U2   | Поддержка MicroFrontend-архитектуры с использованием React.                               | Облегчает поддержку и параллельную разработку различных компонентов. |
| U3   | Адаптация дизайна к фирменному стилю банка.                                               | Сохраняет узнаваемость бренда и повышает доверие клиентов. |
| U4   | Минимум действий для открытия счета — упор на автоматизацию.                              | Уменьшает барьеры для новых клиентов и повышает удовлетворенность. |
| R   | Надёжность (Reliability)                                                           |             |
| R1   | Высокая доступность приложения за счёт отказоустойчивой архитектуры.                      | Обеспечивает непрерывную работу критических бизнес-функций. |
| R2   | Возможность восстановления после сбоев.                                                    | Минимизирует потери данных и снижает время простоя. |
| R3   | Регулярное резервное копирование данных.                                                   | Гарантирует сохранность информации при сбоях и атаках. |
| P   | Производительность (Performance)                                                    |             |
| P1   | Отклик пользовательского интерфейса должен составлять не более 300 мс.                    | Улучшает пользовательский опыт и удовлетворенность. |
| P2   | Перевод монолита АБС на микросервисную архитектуру.                                       | Позволяет масштабировать только необходимые модули. |
| P3   | Внедрение очередей Kafka для масштабируемости.                                            | Повышает устойчивость системы к пиковой нагрузке. |
| P4   | Горизонтальное масштабирование базы данных и сервисов.                                   | Позволяет обслуживать большее количество клиентов. |
| S   | Поддерживаемость (Supportability)                                                 |             |
| S1   | Перевод на PostgreSQL как opensource СУБД.                                                | Снижает затраты на лицензии и упрощает сопровождение. |
| S2   | Документирование архитектуры и модулей для дальнейшего расширения.                        | Обеспечивает преемственность и масштабируемость. |
| S3   | Модульность системы — упрощение внедрения изменений.                                      | Уменьшает время и риски при внедрении новых функций. |
| S4   | Выделение СМС-сервиса в отдельный компонент, независимый от поставщика.                   | Увеличивает гибкость в выборе или смене провайдера. |
| +R  | + Ограничения (Restrictions)       |              |
| R1   | Design Constraints: Использование React + MicroFrontend.                                  | Позволяет разрабатывать и развертывать компоненты независимо. |
| R2   | Design Constraints: Учет корпоративного UI/UX гайдлайна.                                  | Гарантирует единообразие пользовательского интерфейса. |
| R3   | Implementation Requirements: Интеграция с СМС-провайдером через отдельный сервис.         | Упрощает замену провайдера и снижает связанность. |
| R4   | Implementation Requirements: Использование PostgreSQL, отказ от MS SQL/Oracle.            | Снижает затраты и увеличивает гибкость. |
| R5   | Interface Requirements: REST API между фронтом и микросервисами.                          | Стандартизирует взаимодействие между компонентами. |
| R6   | Interface Requirements: API для модуля управления ставками.                               | Позволяет централизованно управлять ставками. |
| R7   | Security Requirements: Шифрование персональных данных (ФИО, телефон, депозиты).           | Обеспечивает соответствие законодательству и защиту данных. |
| R8   | Security Requirements: Безопасное хранение и передача информации.                         | Предотвращает утечку или несанкционированный доступ. |
| R9   | Legal & Compliance: Соответствие требованиям ЦБ РФ и 152-ФЗ.                              | Необходимое условие для легальной работы с персональными данными. |
| R10  | Legal & Compliance: Логирование всех операций и согласий пользователя.                    | Позволяет отслеживать действия и защищаться от спорных ситуаций. |
